# 코드 리뷰 일본어 표현

## 1. 메서드 네이밍 변경 이유

### Q1. なぜ `paid_order_list` を `print_order_summary`に変更したのですか。

`paid_order_list`という名前では、注文の一覧を返すメソッドだと誤解される可能性があります。
実際には注文の情報と合計金額を出力するため、処理の目的がより明確になる `print_order_summary`に変更しました。

`paid_order_list` という名前（なまえ）では、注文（ちゅうもん）の一覧（いちらん）を返（かえ）すメソッドだと誤解（ごかい）される可能性（かのうせい）があります。
実際（じっさい）には注文（ちゅうもん）の情報（じょうほう）と合計金額（ごうけいきんがく）を出力（しゅつりょく）するため、処理（しょり）の目的（もくてき）がより明確（めいかく）になる `print_order_summary` に変更（へんこう）しました。

- `paid_order_list`는 주문 목록을 반환하는 메서드로 오해할 가능성이 있음
- 실제 역할은 주문 정보와 총금액 출력
- `print_order_summary`로 변경하여 메서드의 목적을 명확하게 표현

## 2. Guard Clause 사용 이유

### Q2. なぜ `next unless` を使ったのですか。

条件分岐のネストを減らし、コードの可読性を高めるためです。
処理対象ではない注文を先にスキップすることで、メインの処理が分かりやすくなると考えました。

条件分岐（じょうけんぶんき）のネストを減（へ）らし、コードの可読性（かどくせい）を高（たか）めるためです。
処理対象（しょりたいしょう）ではない注文（ちゅうもん）を先（さき）にスキップすることで、メインの処理（しょり）が分（わ）かりやすくなると考（かんが）えました。

- 조건문의 중첩을 줄이고 가독성을 높이기 위함
- 처리 대상이 아닌 주문을 먼저 건너뜀
- 주요 처리 로직을 이해하기 쉽게 개선

## 3. Magic Number를 상수로 변경한 이유

### Q3. なぜ `100000` を定数に変更したのですか。

`100000`という数字だけでは、その意味が分かりにくいためです。
`LARGE_ORDER_THRESHOLD`という定数にすることで、金額の判定基準が明確になり、将来の変更にも対応しやすくなると考えました。

- `100000`이라는 숫자만으로는 의미를 파악하기 어려움
- 상수명으로 금액의 판정 기준을 명확하게 표현
- 향후 기준이 변경되어도 유지보수하기 쉬움

## 4. 짧은 답변

1. 네이밍 변경 이유

- メソッドの役割を明確にするためです。

2. Guard Clause 사용 이유

- ネストを減らし、可読性を高めるためです。

3. 상수 사용 이유

- 数字の意味を明確にし、保守性を高めるためです。

## 5. 일본어 단어

- 可読性（かどくせい） 가독성
- 保守性（ほしゅせい） 유지보수성
- 一貫性（いっかんせい） 일관성
- 命名（めいめい） 네이밍
- 処理（しょり） 처리
- 条件分岐（じょうけんぶんき） 조건 분기
- 明確（めいかく） 명확함
- 変更（へんこう） 변경
- 定数（ていすう） 상수
- 判定基準（はんていきじゅん） 판정 기준
- 改善（かいぜん） 개선
- 重複（ちょうふく） 중복
